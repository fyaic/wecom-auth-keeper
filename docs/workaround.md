# 七天能力授权的临时续期方案

[返回首页](../README.md) · [部署指南](getting-started.md) · [实测证据](validation.md)

**已有可操作 Mac 的用户，可以用桌面脚本完成指定权限的取消并重新授权，临时减少重复点击。** 本项目是社区方案，使用企业微信正常授权界面，不提供官方续期接口，也不改变平台的授权期限。

截至 2026-09-23，已核查的官方公开资料中未发现七天能力授权的无人值守续期方案；详见[官方支持核查](official-status.md)。

## 适用条件与自动化范围

- macOS、已登录企业微信、具备目标机器人授权资格的用户会话，以及 Python 的辅助功能权限。
- 预续期前打开正确机器人的管理详情 → “可使用权限”页面；程序校验页面中的两项机器人 ID。
- 脚本按 `target_rows` 白名单逐项滚动、取消、重新授权、核对新有效期。取消前落盘恢复记录；失败优先恢复当前项。
- 页面导航尚未自动化。纯 Linux 服务器、锁屏运行、无人协助的完整七天循环不在本次验证范围内。

| 路径 | 触发方式 | 当前验证范围 |
|---|---|---|
| 到期后恢复 | `--renew`；或文档双探针触发 `keepalive.py` | 原生产实现有历史恢复记录；新版有回归测试，不能混同为新版长期实测 |
| 到期前续期 | 单独调用 `--pre-renew --existing-window`，默认处理 24 小时内到期项 | 新版独立脚本三项真实操作通过，重开页面复核一致 |
| 每小时 launchd 示例 | 执行 `keepalive.py` | 到期后恢复，不会定时主动调用预续期 |

## 最小复现

先按[部署指南](getting-started.md)安装依赖，复制示例配置并填写目标机器人身份。白名单示例（合并到自己的配置，不是完整配置文件）：

```json
{
  "target_rows": [
    "新建与编辑文档",
    "搜索与获取文档内容",
    "搜索企业成员"
  ]
}
```

文档只读时仅保留 `搜索与获取文档内容`。未列出的权限不会被操作；“授权”按钮也可能代表从未授权，白名单应只包含你明确希望授予该机器人的能力。

在目标权限页已打开的前提下：

```bash
# 记录原状态与有效期，不修改授权
.venv/bin/python renew.py --config config.json --check --existing-window

# 逐项处理 24 小时内到期的权限；更远的有效授权会跳过
.venv/bin/python renew.py --config config.json \
  --pre-renew --existing-window --within-hours 24

# 关闭并重新打开权限页，再复查
.venv/bin/python renew.py --config config.json --check --existing-window
```

判断是否发生续期时，比较输出的 `expiry_before` 与 `expiry`；仅有 `ok=true` 也可能表示权限尚远于阈值而被跳过。确认 `pending_recovery=false`，再验证你实际使用的业务接口。文档探针会覆盖专用测试表的 A1，不要指向业务数据；通讯录尚无内置业务探针。

## 已验证结果

2026-09-22（Asia/Shanghai），企业微信 `5.0.11.99998`，Python 3.14、PyObjC 12.2.2：

| 能力 | 操作前有效期 | 操作后及重开页面复查 |
|---|---|---|
| 新建与编辑文档 | 9/22 18:39 | 9/29 16:18 |
| 搜索与获取文档内容 | 9/22 18:39 | 9/29 16:18 |
| 搜索企业成员 | 9/22 18:39 | 9/29 16:18 |

三项此前均已授权；同一机器人未纳入白名单的消息权限保持原日期。页面由桌面代理打开，三项续期由独立脚本完成；没有运行业务 API 探针。44 项本地回归及 Linux/macOS CI 通过，但这不能代替跨周期可靠性证据。

## 使用边界与后续方向

取消和重授之间存在短暂未授权窗口，可能影响并发业务调用；持久化记录和重试不能保证必然恢复或零中断。不要将本方案宣传为永久授权或纯服务端自动续期。

我们仍希望官方提供按能力的 `expires_at` / `needs_reauth`、明确的 `850003` 处置方式，以及管理员可控的长期授权或续期入口。相关讨论：

- [wecom-cli #138：更长有效期、永久授权与自动续期](https://github.com/WecomTeam/wecom-cli/issues/138)
- [wecom-cli #134：文档读写分开过期与 850003](https://github.com/WecomTeam/wecom-cli/issues/134)
- [wecom-cli #87：授权有效期可观测性（消息能力）](https://github.com/WecomTeam/wecom-cli/issues/87)

消息能力未纳入本次续期测试，不能从文档和通讯录的结果推断其已通过验收。
