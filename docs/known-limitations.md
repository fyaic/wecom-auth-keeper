# 已知限制

状态：2026-09-21，针对当前 `renew.py` 与保活脚本。以下问题尚未在本次仓库文档整理中修复。

| 优先级 | 问题 | 影响 |
|---|---|---|
| P1 | `read_rows` 以“没有授权按钮”推断已授权 | 部分加载、控件缺失可能被当成健康 |
| P1 | `main` 在行 missing 或续期失败时仍可能返回 `ok=true` / 0 | 调用方不能仅凭退出码判成功；需实际 CLI 复探 |
| P1 | 授权链接、权限窗口、确认按钮搜索范围过宽，未严格绑定 bot 身份 | 多窗口、多 bot 情况存在误选风险；尚未做实机误选测试 |
| P1 | `activate` 比较方法对象而非 `processIdentifier()` 返回值 | 激活步骤被跳过，可能依赖 bridge 切会话掩盖 |
| P1 | 保活只处理 850003；其他错误和部分提前退出不通知 | 网络错误、配置错误、解析失败可静默失败 |
| P2 | state 保存续期前快照 | 下次判断可能读取旧有效期 |
| P2 | 坐标解析不接受负数 | 副显示器布局可能无法定位控件 |
| P2 | 外部 bridge 依赖、CLI 路径硬编码 | 新环境不能直接复制运行 |

其他边界：

- `--check` 仍会操作桌面、写状态，并可能投递链接消息与修改 monitor 模式。
- monitor 结束时一律设为 active，没有恢复原模式；消息发送开关与 GUI 协调耦合。
- 读探针没有显式超时；过期锁靠时间删除，并非可靠的进程生命周期互斥。
- 当前 stdout 混有 JSON 和日志，不是稳定的机器读取协议。
- README 旧版“到期空窗 ≤1 小时”只描述正常小时调度的检测等待；失败、休眠、离线时没有该上限。
- 当前脚本不支持预续期；[实机成功](validation.md)尚需工程集成。

修复优先级和验收方式见[路线图](roadmap.md)。欢迎提供[脱敏的 bug 报告](https://github.com/fyaic/wecom-auth-keeper/issues/new/choose)。
