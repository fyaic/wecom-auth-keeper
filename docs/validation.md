## 2026-09-21：未到期预续期实机验证

环境：macOS、企业微信；权限页 URL 显示客户端版本 `5.0.11.99983`。通过 Codex 桌面自动化会话操作既有机器人的两条文档权限。CLI 与 bridge 版本不适用本次点击链路：本次未运行二者的业务探针。时间均为 Asia/Shanghai。

| 能力 | 操作前 | 操作后 | 关闭页面后重新打开 |
|---|---|---|---|
| 搜索与获取文档内容 | 已授权，9/22 18:01 | 已授权，9/28 16:36 | 相同 |
| 新建与编辑文档 | 已授权，9/22 18:01 | 已授权，9/28 16:39 | 相同 |

为避免公开企业信息，本页不附含账号身份、聊天内容和完整授权 URL 的原始截图。表中数值是现场观察记录，贡献者可按下述流程独立验证。

### 成功路径

1. 打开目标机器人聊天，点击顶部名称，在资料卡点“去管理”。
2. 进入“管理”，从企业创建列表找到同一机器人，点“详情”。
3. 再次核对机器人名称与简介，打开“可使用权限”。
4. 等完整 Accessibility 树出现，记录两条能力的授权状态及有效期。
5. 点目标行“已授权”下拉，点“取消授权”，在确认弹窗继续。
6. 等该行出现“授权”按钮，再点击该行授权。
7. 等“已授权”和新的有效期同时出现，确认后再处理下一条。
8. 关闭权限页并重新打开，复核结果。

取消后确实观察到未授权状态，重新授权后有效期变为操作时刻七天后；全程无需扫码或人工点击。其他能力未变更。

### 技术发现

- “取消授权”藏在“已授权”的下拉菜单中；本次以 AX 文本元素出现。只枚举 AXButton 或在初始页面查找，不足以判断入口不存在。
- 权限页可读出能力名、状态、日期及操作控件，适合实现带前后条件检查的状态机。
- 管理列表和详情页主要暴露外层 container，本次部分导航依赖截图与坐标点击。这部分尚未形成稳定的独立脚本。
- 该入口 URL 含 `from=flutter`，原脚本使用聊天入口 `from=chat`。尚未做参数受控对照，不能声称只改参数就能打开取消菜单。
- 点击返回时状态可能尚未更新，必须等待实际状态转换。

### 结论边界

证明了：**未到期权限可以通过桌面自动化取消并重授，刷新七天有效期。**

未证明：现有 `renew.py` 支持该流程、脱离桌面代理的全链路脚本、业务 API 读写恢复、锁屏运行、多机器人隔离或跨多个七天周期的可靠性。取消与重授不是原子操作，期间可能影响业务调用。

## 2026-09-22：独立实现与回归验证

新增内置 PyObjC AX 适配层，移除 bridge 源码依赖；状态判定、身份校验、JSON 退出协议、进程锁、状态原子写入、双探针与告警均已重构。

新增 `--pre-renew --existing-window`：只操作已经打开并验证身份的页面，按到期阈值逐条取消/重授。取消前保存本地恢复记录，失败后优先尝试重授；未恢复则保留记录、停止后续行，下一次 `--renew` 优先处理该记录。

验证分层：标准库测试覆盖状态机、故障恢复和实际子进程/shell 入口；macOS 原生依赖测试只构造 AX 几何值并模拟应用发现，不读真实聊天、不点击或授予权限。初版提交时尚未完成真实账号重授权；下节记录后续实机验收。管理列表导航和跨周期运行仍未验收，不能把 9 月 21 日桌面代理的成功直接归属于新代码。


## 2026-09-22：独立脚本三项预续期实测

macOS，企业微信 `5.0.11.99998`，本地 Python 3.14 / PyObjC 12.2.2，时间 Asia/Shanghai。桌面代理仅负责打开目标管理权限页及复查；取消、确认、重新授权和跨行滚动由 `renew.py` 独立完成。未运行 CLI/bridge 业务探针，未发送消息。

| 配置中的能力 | 操作前有效期 | 操作后及重开页面复查 |
|---|---|---|
| 新建与编辑文档 | 9/22 18:39 | 9/29 16:18 |
| 搜索与获取文档内容 | 9/22 18:39 | 9/29 16:18 |
| 搜索企业成员 | 9/22 18:39 | 9/29 16:18 |

同一机器人消息权限仍为 9/22 18:39，未被操作。三项原本均已授权，本次没有增加能力范围。

复现步骤：配置上述三行及目标机器人双 ID；打开管理权限页；执行 `renew.py --config <private-config> --check --existing-window`，确认原有效期；执行 `--pre-renew --existing-window`（默认 24 小时阈值）；关闭并重新打开权限页，再执行只读检查。最终两次检查均 `ok=true`，续期返回三项新日期且 `pending_recovery=false`。

首次实跑暴露了无窗口同名进程、通讯录标题与说明重复、页面外控件及鼠标点击时序问题。修复后一次脚本运行完成全部三项。修复前尝试停在撤销确认之前，未撤销权限。当前实现过滤无窗口进程、按标题列区分说明文字、滚动后复查页面边界，并在鼠标按下/抬起间保留事件处理时间。

这证明了已打开管理页面上的独立脚本预续期。尚未证明从任意桌面状态无人值守进入页面、业务 API 的读写恢复、锁屏运行、跨账号或多个七天周期的可靠性。
