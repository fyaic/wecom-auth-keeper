## 分层结构

1. **分发层**：ZIP + 外部 SHA-256 + 包内 manifest；固定提交、明确支持范围。包是源码安装包，依赖安装需要网络；不是已签名离线应用。已包含主线核心实现，排除专属部署和原始诊断。
2. **安装层**：标准库 onboard 跨平台检测；macOS 由本机 CLI 身份、官方授权链接和用户白名单生成私有配置。没有全局共享 config，没有发包人 Bot ID。
3. **适配层**：现有 macOS AX 模块，组织/聊天/页面只是导航阶段；最终操作仍绑定两个 Bot 标识。页面、企业行按结构和身份核验；5.0.13 企业菜单入口有经过版本限制的相对窗口位置适配，不承诺对未知布局可用。
4. **策略层**：复用 keeper_maintenance，多权限逐项期限、冷却、pending、失败退避、全周期桌面锁及超时。默认每小时、提前24小时。
5. **验收层**：配置、后台只读检查、真实续期、业务探针、跨周期观察分别记录。agent 写验收记录而不是自称“部署成功”。
6. **运维层**：失败清理、私有日志、升级回滚、任务去重；不自动上传、不自动替换页面适配代码、不通过模型每小时盲点 UI。

## 多组织与 UI 更新的发布门槛

本分支移除最大窗口/头像/聊天文本包含关系的旧企业选择逻辑。默认不启用自动切换；5.0.13 可配置精确菜单名称及 sidebar-5.0.13 适配器。入口 AX 几何失真时只做受版本限制的相对窗口点击；真正选择依据是独立企业菜单的 icon corp list 与 checkmark、唯一精确名称。切换后重新取窗口并复查选中项，再进入双 Bot 身份验证。未知客户端版本拒绝此适配器，不尝试取消任何权限。

回归覆盖近似/重复企业名、聊天文本伪装、缺少选中项、切换失败及菜单清理。不同设备分辨率、布局和系统授权仍须现场验收，不能从本机成功外推全部设备。
企业微信升级后先停用失败的适配路径并输出固定错误码。诊断默认只收版本、结构计数、操作阶段、是否发现身份绑定页面；原始 AX 文本/URL 只能本地检查，不作为群内回传材料。新增布局必须经过同一后台启动链验收。当前包不含会输出原始聊天文本与 URL 的 inspect_compat.py。

## 与其他桌面服务共存的缺口与接入要求

当前 `desktop.lock` 只约束同样使用该锁的 Keeper 进程。远端 Bridge 并不持有该锁；其 observe 模式仍允许组织轮转和部分弹窗恢复。因此当前候选在检测到 Bridge 轮转启用时拒绝导航和续期，不提供生产互斥实现，也不允许把这个前置拒绝写成“问题已解决”。

后续接入应提供双方认可的有期限独占协议，满足以下条件后才能解除拒绝：

- 申请独占时禁止新 UI 动作，并等待已经开始的组织切换、读取、发送和弹窗恢复退出；只改一个监控枚举或观察一次“空闲”会存在竞态。
- 独占覆盖整个维护周期，包括身份导航、逐项续期、恢复 pending、关页。Bridge 的监控轮转、主动读、发送队列、直接 UI API、弹窗恢复均须遵守；HTTP 存活和看门狗应持续工作，不能冻结整个进程。
- 租约需有所有者、不可混用的凭证和有效期；仅同一所有者能释放。失效必须使 Keeper 在下一次取消授权之前停止，已取消项按恢复契约处理。TTL、最大维护时长及恢复预算必须相容，不能 TTL 到期时两个程序同时开始点击。
- 释放后重新读实际组织和窗口，清理过期缓存，恢复先前监控策略。异常退出、超时、断连、服务重启均要测试；不能靠 AI 或人工重新启动服务完成恢复。
- 在未改动 Bot 授权的只读阶段先验证互斥，再测试真实续期及服务恢复；测试必须包含正在轮转、正在处理已有工作、租约冲突、崩溃和超时。禁止为测试发送未获用户授权的业务消息。

该接入需要 Bridge 自身配合，单靠修改 Keeper 不能保证任意第三方 UI 服务都会避让。业务安装包不应现场改写另一项目的生产源码；支持范围应按实际共存验收结果声明。未知 UI 操作者或人工占用仍需通过焦点、页面和身份校验立即中止。

## Windows 实现设计与验收门槛

不能直接复用 PyObjC、fcntl、launchctl。未来 Windows 后端应单独实现，而不是让 Agent 临时拼出未经测试的自动点击脚本：

- UIA provider：发现 WeCom 进程与登录会话；返回唯一窗口、语义控件、可证明的官方目标页身份；无双身份可见证据时拒绝授权。
- navigator：活动组织/候选组织区分、完整 Bot 名、链接双身份，禁止“同名即同 Bot”。对弹窗与加载采用有限等待、重新取控件，避免缓存坐标。
- mutator：逐项读取状态/日期、取消前落盘 intent、恢复优先、证实日期延长；重用状态机契约，不能把 AX role 字符串硬翻译为坐标。
- host adapter：用 Windows 文件锁/命名互斥体代替 fcntl，文件 ACL 代替仅 chmod；Task Scheduler 使用用户交互登录会话（不是服务/session 0），开机但未登录不能算可运行。
- cleanup：只关本周期身份核验通过的权限窗口；不得退出整个企业微信。
- acceptance：真实 Windows 10/11、各目标客户端、多个 Bot/组织、缩放及多显示器；测试锁屏/断网/进程中断/凭据不符/多权限部分失败。至少一个自然提前续期周期和同 Bot 业务复查，才能发布支持 Windows 的正式包。

建议抽象后端操作：discover_session、inspect_active_organization、navigate_target、read_permissions、revoke_one、grant_one、close_target；策略层只消费身份绑定的观察与动作结果。接口文档不等于 Windows 已实现。本分支仅保证 bootstrap 在 Windows 路径安全拒绝自动化，尚无 Windows 实机测试。

## 版本和分发

预览版文件名带日期和提交短号；未来稳定版按 SemVer 发布：补丁修布局/诊断，次版本加已验证能力，主版本变更配置/恢复协议。macOS 与 Windows 的支持标记必须分别声明，可分别放行，不能统一写“跨平台已支持”。

构建只从提交中的固定文件列表取内容，拒绝核心文件未提交修改。执行 `python3 delivery/build_bundle.py --output /absolute/output/keeper-agent-preview.zip`。验证解压、manifest、无私有文件、无发包人路径、所有运行入口导入完整，然后交付 ZIP、外部校验文件及 START-HERE.md。不能直接压缩本地项目目录，也不包含 .git、.venv、私有输入、日志、状态或专属部署文档。

macOS 正式版本还需：不同 Mac 从空环境安装、同真实后台链路实际续期、组织身份核验及组织切换回归、既有 UI 服务共存和异常恢复测试。当前远端独立 Kimi 演练失败，不能用旧引擎在维护者本机的成功替代。Windows 后端与实体环境验证是单独的支持发布门槛，不阻止将来只发布 macOS 版；当前不支持 Windows。签名/notarization/依赖镜像可另行建设。
