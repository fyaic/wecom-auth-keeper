# 已知限制

更新：2026-10-23。本次重构已修复旧实现的“缺少按钮即已授权”、无条件 `ok=true`、旧状态保存、进程激活、负坐标、探针缺超时和 shell 错误吞没等问题，详见[验证记录](validation.md)。

## 仍需验证和改进

- 已有文档读写、通讯录的现有页面预续期证据，以及 10/23 新版客户端上的后台聊天导航、消息权限预续期和独立只读业务复查。干净 Mac、旧版回归和跨七天周期仍未验证，详见[兼容矩阵](compatibility.md)。
- 2026-10-23 新增可选 `chat_history_navigation` 原生聊天记录导航。该入口要求目标聊天已有
  身份匹配的官方授权链接，当前使用中文界面；不自动切换企业、不创建链接、不发送消息。
  全局搜索结果在 5.0.12 上不暴露 AX，程序只用 Return 导航到候选会话，再校验标题、链接双身份
  和实际页面身份。找不到目标时退出，不从同名前缀推断机器人身份。
  文字输入仅允许已聚焦的原生 AXTextField；搜索结果选择不会向聊天输入框发送 Return。
  修改前台窗口会使键盘步骤停止；导航会临时使用系统剪贴板，并在未被用户更新时恢复原格式。
  后台任务仍要求用户桌面已登录、解锁且进程有辅助功能权限，不保证锁屏或多组织自动切换。
- 周期关页是可选功能，仅对唯一、身份匹配且具有原生关闭按钮的权限窗口操作；关闭失败会报错。不会恢复原会话或自动协调其他 UI 服务，进程被强杀时不保证清理。
- 预续期必须使用 `--existing-window`，目标权限页需已经打开；目标控件自动滚动已实现，管理列表自动导航尚未实现。
- 新增 `maintain.py` 独立调度按每项页面有效期提前续期，支持多权限配置；其业务验证仍为 false。多能力组合有回归覆盖，不能等同于本版每种能力都实机验收。部署见[独立定时维护](scheduled-maintenance.md)。
- 旧 `keepalive.py` 每小时保活只根据文档读写探针错误或待恢复记录触发恢复，不按到期时间自动预续期。通讯录没有内置业务探针。
- `target_rows` 限制操作范围，但页面的“授权”按钮无法区分从未授权与过期，不能将白名单当成“只恢复历史授权”的检测器。
- AX 状态关联仍使用行内相对几何关系。未知或不完整布局会失败关闭；需要更多客户端/窗口布局兼容性记录。
- 必须读到身份匹配的授权页 AXWebArea URL。若客户端不暴露 URL，当前拒绝操作，不退回仅凭标题判断。
- 取消和重授不是原子操作。恢复记录、重试和后续恢复可以减少风险，但不能保证取消期间无业务失败或必然恢复。
- CLI 凭据归属由部署者确认，当前没有自动将 CLI 登录身份与目标页面 bot 参数交叉比对。错误码 0 只证明配置的探针操作成功。
- `--check` 不改授权、消息或 monitor，但可打开已有链接并写状态；`--doctor` 不操作 GUI，也不检查登录、辅助功能授权或真实 API 能力。
- 原生 AX 调用可能受客户端卡死影响。保活对子进程有总超时；直接调用 `renew.py` 时没有外部进程 watchdog。
- monitor 协调需要显式配置可用的 bridge。已配置但无法确认原模式时拒绝变更；网络故障导致恢复原模式失败仍需人工处理。
- 所有参与桌面操作的工具需要共同协调。本项目的 GUI 锁只约束使用同一锁协议的本项目进程。
- 通知仅在配置 bridge 与收件人时生效；配置文件自身损坏时只通过非零退出码/stdout 报告，无法依赖其中的收件人配置发送通知。
- 保活和探针的 shell 输出已改成 JSON，旧文本解析器需迁移。未提供旧格式兼容模式。

修复优先级和验收方式见[路线图](roadmap.md)。欢迎提供[脱敏的问题报告](https://github.com/fyaic/wecom-auth-keeper/issues/new/choose)。
